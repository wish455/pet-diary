# 部署到公网（给其他人使用）

本项目已经是**多用户**形态：每个人注册自己的账号，只能看到自己的宠物数据。
下面按「最省事」到「最可控」列出三种方式，选一种即可。全部**不需要改动代码**。

> 重要前提：公网访问**必须用 HTTPS**。否则登录 Cookie 会被浏览器拒绝或明文传输。
> 下面三种方式都会自动提供 HTTPS。

---

## 方案一：Render（最省事，推荐先试）

优点：连 GitHub 自动部署、自动 HTTPS、自带域名；缺点：免费套餐没有持久磁盘，容器重启会丢数据。

### 步骤

1. 把项目推到 GitHub（在项目目录执行，先把 Git 仓库初始化好）：

   ```bash
   git init
   git add .
   git commit -m "宠物管理系统"
   git branch -M main
   git remote add origin https://github.com/你的用户名/pet-diary.git
   git push -u origin main
   ```

   `.gitignore` 已经排除了 `data/`、`.env`，不会把数据库和密钥传上去。

2. 打开 <https://dashboard.render.com> → 注册并登录 → **New +** → **Blueprint** → 选择这个仓库。
   Render 会读取仓库里的 `render.yaml`，自动创建服务、磁盘和环境变量。

3. 首次部署完成后，打开 Render 给的网址（形如 `https://pet-diary-xxxx.onrender.com`）。

4. **注册第一个账号**，它就是管理员。之后把网址发给朋友，让他们各自注册即可。

### 关于数据持久化（重要）

- `render.yaml` 里默认 `plan: starter`，会给一块 1GB 持久磁盘挂到 `/data`，数据长期保留（约 $7/月）。
- 如果想先免费试：把 `plan` 改成 `free`。免费套餐**不能挂磁盘**，容器重建（重新部署、休眠唤醒失败等）后账号和记录会清空，只适合演示。
- 无论哪种套餐，都建议定期在「数据中心 → 导出我的全部数据」做备份。

### 关闭注册 / 设置邀请码

在 Render 的 **Environment** 里改环境变量（改完会自动重新部署）：

| 变量 | 作用 |
| --- | --- |
| `OPEN_REGISTRATION=0` | 完全关闭注册，只有已有账号能登录 |
| `INVITE_CODE=你的邀请码` | 注册必须填对邀请码才能创建账号 |
| `ADMIN_USERS=用户名` | 启动时把该账号提升为管理员 |

## 方案二：Railway / Fly.io（同样连 GitHub）

### Railway

1. <https://railway.app> → New Project → Deploy from GitHub repo → 选择仓库（会自动识别 `Dockerfile`）。
2. 在服务的 **Variables** 里加：
   `NODE_ENV=production`、`DATA_DIR=/data`、`HOST=0.0.0.0`、`COOKIE_SECURE=true`。
3. 在 **Volumes** 里给服务挂一个卷，挂载路径填 `/data`。
4. Settings → Networking → Generate Domain，得到 `https://xxx.up.railway.app`。

### Fly.io

```bash
fly launch --no-deploy        # 生成 fly.toml，选择 Dockerfile 部署
fly volumes create petdata --size 1
```

在生成的 `fly.toml` 里确认/补充：

```toml
[env]
  NODE_ENV = "production"
  DATA_DIR = "/data"
  COOKIE_SECURE = "true"

[[mounts]]
  source = "petdata"
  destination = "/data"
```

```bash
fly deploy
fly open          # 打开分配的 https 地址
```

## 方案三：自己的云服务器 + 域名（数据完全在手里）

适合长期使用。以 Ubuntu 22.04 轻量服务器为例（腾讯云/阿里云/Vultr 都行）。

### 1. 装 Docker

```bash
curl -fsSL https://get.docker.com | sh
```

### 2. 拉代码并启动

```bash
git clone https://github.com/你的用户名/pet-diary.git
cd pet-diary
cp .env.example .env      # 按需修改（建议 COOKIE_SECURE=true）
docker compose up -d --build
docker compose logs -f    # 看到 "running" 即成功
```

此时服务监听 `127.0.0.1:3000` 之外的 `0.0.0.0:3000`，但**先别直接开 3000 端口**，用下面的反向代理加 HTTPS。

### 3. 用 Caddy 自动申请 HTTPS 证书（最简单）

把域名 A 记录解析到服务器 IP，然后：

```bash
docker run -d --name caddy --restart unless-stopped \
  --network host \
  -v caddy_data:/data -v caddy_config:/config \
  caddy caddy reverse-proxy --from 你的域名.com --to 127.0.0.1:3000
```

Caddy 会自动申请并续期证书。浏览器访问 `https://你的域名.com` 即可。

### 4. 用 Nginx 的话（等价配置）

```nginx
server {
    listen 443 ssl http2;
    server_name 你的域名.com;

    ssl_certificate     /etc/letsencrypt/live/你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名.com/privkey.pem;

    client_max_body_size 12m;          # 上传图片用，需大于 MAX_UPLOAD_MB

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
server {
    listen 80;
    server_name 你的域名.com;
    return 301 https://$host$request_uri;
}
```

证书用 `certbot --nginx -d 你的域名.com` 申请即可。

### 5. 更新版本

```bash
git pull
docker compose up -d --build
```

数据库在宿主机的 `./data` 目录里，重建容器不会丢。

## 部署后必做的三件事

1. **注册第一个账号**（自动成为管理员），并在左下角账号菜单里**改掉默认密码**。
2. **关闭注册或设置邀请码**：不想让陌生人注册就把 `OPEN_REGISTRATION=0`；想给朋友用就设 `INVITE_CODE`。
3. **定期备份**：在「数据中心 → 导出我的全部数据」下载 JSON；整站备份也可以直接打包服务器的 `data/` 目录。

## 环境变量总览

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口（平台一般会自动注入） |
| `HOST` | 生产 `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | 数据库与上传图片目录，容器部署务必指向挂载卷 |
| `NODE_ENV` | — | 设为 `production` 时自动开启 HTTPS Cookie 与 HSTS |
| `COOKIE_SECURE` | 生产 `true` | 通过 HTTPS 访问保持 `true`；纯 http 调试设 `false` |
| `SESSION_DAYS` | `30` | 登录状态保持天数 |
| `OPEN_REGISTRATION` | `1` | `0` = 关闭注册 |
| `INVITE_CODE` | 空 | 填写后注册必须输入邀请码 |
| `ADMIN_USERS` | 空 | 逗号分隔，启动时把这些账号提升为管理员 |
| `MAX_UPLOAD_MB` | `8` | 单张图片上传上限 |
| `SHOT_TOKEN` | 空 | **仅开发用**，开启自动化截图调试通道，生产环境不要设置 |

## 常见问题

**Q：打开页面一片空白 / 一直停在登录页？**
F12 看 Console 与 Network。若 `/api/auth/status` 报错，多半是 `DATA_DIR` 不可写（容器里要挂载卷并确保有写权限）。

**Q：登录后立刻掉线？**
99% 是 HTTPS 环境变量不匹配：用 `https://` 访问时 `COOKIE_SECURE` 必须是 `true`；用纯 `http://` 调试时必须设 `false`。

**Q：图片上传失败？**
检查反向代理的 `client_max_body_size` 是否大于 `MAX_UPLOAD_MB`，以及挂载目录剩余空间。

**Q：免费套餐数据丢了？**
免费套餐通常没有持久磁盘。改用带磁盘的套餐，或自建服务器（方案三），并养成导出备份的习惯。

**Q：忘记管理员密码怎么办？**
在服务器上直接改数据库（把旧的 `demo` 换成你的用户名，密码设成新的临时值，登录后再改）：

```bash
docker compose exec pet-diary node -e "
import('./server/auth.js').then(async (a) => {
  const { db } = await import('./server/db.js');
  const u = db.prepare('SELECT id FROM users WHERE username = ?').get('demo');
  a.updatePassword(u.id, 'newpassword123');
  console.log('已重置为 newpassword123');
});
"
```

**Q：想把站点给别人演示，但不想开放注册？**
设 `INVITE_CODE`，把邀请码单独发给需要的人。
